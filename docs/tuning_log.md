# Unitree Go1 训练调参记录

**项目**：Unitree Go1 四足机器人行走（PPO + MuJoCo）
**最终结果**：1000 步前进 5.00 米

---

## 训练阶段

### 阶段 1：站立训练（20 万步）
- 奖励函数：`reward = 0.1 + (height < 0.15 ? -10 : 0)`
- 目标：让机器人学会不摔倒
- 结果：✅ 能稳定站立 500 步

### 阶段 2：行走训练（30 万步）
- 奖励函数：加入 `forward_vel * 2.0`
- 遇到的问题：方向是反的
- 解决：`forward_vel = -qvel[0]`
- 进一步优化：加入 `displacement * 20.0`
- 结果：✅ 出现前进动作，但步态不稳

### 阶段 3：步态优化（20 万步）
- 奖励函数新增：
  - 高度保持惩罚：`abs(height - 0.45) * 3.0`
  - 颠簸惩罚：`abs(vertical_vel) * 0.5`
  - 动作平滑惩罚：`sum(abs(action - prev_action)) * 0.01`
- 学习率：`3e-4 → 5e-5`
- 结果：✅ 步态稳定，前进 5.00 米

---

## 关键经验

1. 位置控制比 `ctrl` 控制更稳（仿真中）
2. 位移奖励比速度奖励更可靠（速度可造假，位移不能）
3. 奖励函数要分阶段加（先动 → 再稳 → 再优）
4. 方向问题用 `print(qvel[0])` 验证
5. 四足行走需要 50~70 万步，30 万步不够

---

## 主要 Bug 及修复

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 机器人不动 | `ctrl` 信号被稀释 | 改用 `qpos` 控制 + `mj_forward` |
| 方向反了 | `qvel[0]` 定义相反 | `forward_vel = -qvel[0]` |
| 高度索引错误 | 忽略了基座位置在前 3 个元素 | `obs[14]` 是高度 |
| 训练波动大 | 学习率太高 | 从 `3e-4` 降到 `5e-5` |

---

## 如果重新做

1. 直接用 `qpos` 控制，不折腾 `ctrl`
2. 先测方向再训练
3. 分阶段训练，不指望一次成型
4. 保留更多中间模型（便于回溯）
